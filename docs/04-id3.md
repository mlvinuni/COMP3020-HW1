# 4. ID3 decision tree

**Goal:** implement classic categorical, multiway ID3 that outputs a dropout risk and a readable decision path.

Code: `ID3Preprocessor` and `tune_id3` in `main.py`; `ID3Classifier` in `decision_tree.py`.

The model exposes `fit(X, y)`, `predict(X)`, `predict_risk(X)`, `decision_path(row)`, and `tree_stats()`. Pass **already binned** features to the classifier. `TreeNode` stores `(Graduate count, Dropout count)` at every node.

## Column types

Use the same classification for ID3 and kNN.

| Type | Columns |
| --- | --- |
| **Nominal** (categories; codes have no order) | `Marital status`, `Application mode`, `Course`, `Daytime/evening attendance`, `Previous qualification`, `Nacionality`, both parents' qualification and occupation columns, `Displaced`, `Educational special needs`, `Debtor`, `Tuition fees up to date`, `Gender`, `Scholarship holder`, `International` |
| **Numeric** | `Application order`, `Age at enrollment`, the twelve semester measures, `Unemployment rate`, `Inflation rate`, `GDP` |

In your report, explain the assumption that `Application order` has a meaningful rank.

## Required settings

Use **one fixed configuration** for every required ID3 run. There is no required grid search.

| Setting | Value |
| --- | --- |
| `n_bins` | 3 |
| `max_depth` | 3 (root depth is 0) |
| `min_samples_split` | 10 |
| Gain tolerance | Stop if the best gain is ≤ `1e-12` |
| Feature tie-break | First feature in original column order |
| Majority tie at a node | Predicts 0 (Graduate) |

`min_samples_split` limits the size of the **parent** node, not of each child. `fit` must reject a negative `max_depth` or `min_samples_split < 2` with `ValueError`; `max_depth=0` produces a single root leaf.

The tiny model tests use `min_samples_split=2` so that splits happen on small fixtures. Keep the experiment setting at 10. The class must still accept `max_depth=None` (unlimited depth), even though the required runs use 3.

## What to do

### A. Bin numeric features (`ID3Preprocessor`)

Only the preprocessor handles continuous values. After transformation, the classifier treats every column as a category.

1. In `fit`, compute boundaries from **training rows only** using quantiles for `n_bins` bins. The required runs use 3, but the preprocessor must accept any valid bin count, because the tests check general behavior.
2. Use linear interpolation for the internal quantiles.
3. Remove repeated boundaries and any boundary equal to the observed minimum or maximum. A constant column stores no boundaries. As a result, a feature asked for 3 bins may end up with fewer.
4. In `transform`, number the bins from 0. A value equal to a boundary goes into the **upper** bin. The outer bins accept values beyond the training range.
5. Apply the stored boundaries unchanged to validation and test data.

### B. Entropy and information gain

- `H(S) = -sum(p_c * log2(p_c))`, leaving out zero-probability terms.
- `IG(S, A) = H(S) - sum_v (|S_v| / |S|) * H(S_v)`

Check your formulas on this toy input first: `Course = [1, 1, 2, 2]`, `y = [0, 0, 1, 1]`. The parent entropy is 1 bit. Both Course branches are pure, so the weighted child entropy is 0 and the information gain is 1. A constant column has information gain 0.

### C. Build the tree: `_build_tree(X, y, features, depth)`

1. Count the zeros and ones. Create a `TreeNode` with counts `(zeros, ones)` and prediction `int(ones > zeros)`, so a tie predicts Graduate. Keep these counts even if the node gets children.
2. Return the node as a **leaf** if any of these holds:
   - `y` is pure;
   - `features` is empty;
   - `depth` has reached `max_depth`;
   - `len(y) < min_samples_split`.
3. Compute the information gain of each remaining feature, in original column order. Choose the **first** feature with the maximum gain. If that gain is ≤ `1e-12`, return the leaf.
4. Set `node.feature` to the chosen feature. For **each value observed in the current `X`**:
   - select the matching rows from **both** `X` and `y`;
   - remove the chosen feature from that child's available features;
   - recursively build `node.children[value]` at `depth + 1`.

The classifier does **not** search numeric thresholds, group categories into subsets, prune branches, or calibrate risks.

### D. Predict and explain

| Method | Behavior |
| --- | --- |
| `_traverse(row)` | Start at `root_` and follow the row's value at each split feature. If the value has no child (an unseen category), stop at the **current node**. Never invent an order between category codes. |
| `predict_risk(X)` | `node.counts[1] / sum(node.counts)` at the reached leaf or fallback node: the fraction of training students there who dropped out. This is an empirical score, not a guaranteed calibrated probability. |
| `predict(X)` | `node.prediction` (the majority class; a tie gives 0) |
| `decision_path(row)` | A list with one dict per visited node, including the final leaf or unseen-value fallback node. The docstring gives the exact keys (`feature`, `value`, `counts`, `fallback`). |
| `tree_stats()` | Returns `depth`, `n_nodes`, `n_leaves`. A short recursive walk works: count this node, then sum the children's counts and take the maximum child depth. |

### E. Fit the fixed model: `tune_id3`

Keep the function name for compatibility, but it only fits the model. It does no search:

1. Fit `ID3Preprocessor` with 3 bins on the training rows.
2. Transform the training and validation rows.
3. Fit `ID3Classifier(max_depth=3, min_samples_split=10)`.
4. Compute validation Precision@10% with `capacity_metrics`.
5. Return `(fitted_preprocessor, fitted_classifier, settings_dict)`.

Score validation once, to compare with kNN. Keep this configuration for the test runs and the [Gender-removal run](07-explanations-and-fairness.md#part-d-gender-removal-rerun).
